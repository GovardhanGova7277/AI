Objective

To move from a single-loop AI Agent to an Agentic AI system by orchestrating multiple specialized sub-agents using LangGraph, demonstrating parallel execution, shared state management, and self-correcting feedback loops.

Foundation

Core Concepts

Agent

An LLM placed in a loop — LLM with Hands, LLM + Tool + System Prompt. Given a goal, it can reason and plan, use tools, observe results, and loop until the given goal is achieved.

Tools

A function or method which takes defined inputs/arguments and returns a result or performs an action. Tools act as hands that perform actions — get data, extract data, hit API requests — in external apps or systems.

Graph

A structure of connected nodes with edges. The graph defines the flow of data and control between different units of work, enabling complex orchestration patterns like fan-out, fan-in, and conditional loops.

Nodes

A unit of work in an agent graph. Programmatically, it is a function that receives the current graph state, performs an operation (calling an LLM, tool, API, database, or Python logic), and returns updates to the state.

Orchestration

Multi-Agent Pattern Mapping

The system explicitly realizes the three foundational Agentic AI patterns, each mapped directly to specific nodes and edges in the LangGraph implementation.

Course Pattern Implementation How It Was Realized
Planner–Executor
Delegation 		planner_node → researcher_1,2,3 The Planner LLM decomposes the complex question into 3–5 discrete sub-tasks. It does not execute the research; it only creates the execution plan for the workers.
Orchestrator–Workers
Parallelism 		graph.py Fan-out / Fan-in The graph draws 3 edges from the Planner to researcher_1,2,3. LangGraph executes these in parallel threads. They safely merge their findings using the orchestrator's reducer on the findings state key before feeding into the Synthesizer.
Evaluator–Optimizer
Self-Correction 		critic_node → synthesizer_node A conditional edge routes the Critic's output. If the draft is APPROVED, it goes to END. If NEEDS_REVISION, it loops back to the Synthesizer. An iteration cap (MAX_ITERATIONS = 3) prevents infinite loops.

Cost & Latency Trade-off

Agentic AI trades higher cost and latency for higher reliability. While the single-agent baseline is fast and cheap, it frequently produces shallow answers or hallucinates citations. The multi-agent system consumes significantly more Groq tokens (due to multiple planner/researcher/critic calls) and takes longer in theory, but yields structured, multi-perspective briefs with verified citations. In this benchmark, parallel execution actually made the multi-agent system slightly faster than the sequential baseline.

Infrastructure Note

The multi-agent system also experienced rate-limiting (HTTP 429) on the Groq free tier during parallel researcher execution, highlighting the infrastructural requirements of Agentic systems in production deployments.

Reflections

New Perspectives from Building This Project

01

Usage Cost Per Execution

Every LLM call in the agent loop has a real cost. With multiple sub-agents (Planner, 3 Researchers, Synthesizer, Critic), token consumption multiplies rapidly. Tracking cost per execution is essential for production viability.

02

Latency & Response Speed

User experience demands fast responses. Targeting sub-10ms perceived latency requires careful orchestration — parallel execution, streaming outputs, and minimizing sequential LLM calls wherever possible.

03

Security & Guardrails

Agents that can call tools and APIs need robust input/output guardrails. Prompt injection, unauthorized tool access, and leaking sensitive data in LLM responses are real attack surfaces that must be hardened.

04

Evaluation of Agent Trajectories

Final output quality alone is insufficient. Evaluating the full agent trajectory — which tools were called, why the critic looped, whether the planner decomposed correctly — is critical for debugging and improving agent behavior.
