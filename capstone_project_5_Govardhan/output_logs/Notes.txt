What is evaluation?

Evaluation = measuring whether your AI agent is actually doing its job correctly.
How good/reliable is agent.

Evaluating Agents:
1. So you evaluate:

Is the generated answer supported by the provided evidence?

This is often called:

faithfulness
groundedness
attribution

depending on the evaluation framework.

2. When Building Agents this is Important metrics or constraints Is the agent good enough while staying within operational constraints:

Target:

Latency < 10 seconds
Tool calls < 5
Cost < $0.10

------------
For LLM-generated responses, you can use an evaluator model.

For example:

Evaluator LLM


Question:
"What are the benefits of green hydrogen?"


Reference:
"Expected points: X, Y, Z"


Agent answer:
"...."


Evaluator:
Correctness = 8/10
Groundedness = 9/10
Completeness = 7/10

This is often called LLM-as-a-judge.

But here's the catch:

An LLM judge is not automatically ground truth.

The evaluator can itself be wrong or biased.

So for important systems, combine:

Automated metrics
+
Human evaluation
+
Rule-based checks
+
LLM evaluation

What is a guardrail ?
A constraint/check that controls what an AI system is allowed, produce or do.
Why Use guardrail : We restrict what prompts input, outputs and actions is allowed into/from the AI system.

Agent security is not just about preventing bad text. It's about preventing unauthorized actions.

Interview Question : "How would you evaluate an AI agent?"

"I'd evaluate the agent at multiple levels: final answer quality, factuality and groundedness, retrieval quality, tool selection and tool arguments, task completion, trajectory efficiency, latency and cost. I'd build a representative evaluation dataset with expected outcomes and use a combination of deterministic checks, automated metrics, LLM-as-a-judge, and human evaluation for ambiguous cases. I'd also trace individual agent runs so failures can be attributed to retrieval, reasoning, tool use, or generation rather than only judging the final response."
